# 📁 API 명세 (도메인별)

새 API 는 **여기서 AI 와 함께 설계하고**, 팀 합의 후 노션에 반영한다.

> 📖 규칙 전문: [../API.md](../API.md)

---

## 상태 표기 (필수)

모든 엔드포인트에 상태를 단다. **AI 는 이 상태를 보고 구현 여부를 판단한다.**

| 상태 | 의미 | 최신 위치 | 구현 가능? |
|------|------|----------|-----------|
| 📝 초안 | 레포에서 작성 중. 노션 미반영 | **레포** | ❌ **구현 금지** |
| ✅ 확정 | 노션 반영 완료. 프론트가 보고 있음 = 계약 | **노션** | ✅ 가능 |
| 🚧 구현중 | 코드 작성 중 | 노션 | — |
| ✔️ 완료 | 구현 완료 | 노션 | — |

> ⛔ **`📝 초안` 을 구현하면 안 된다.** 노션에 없는 API 를 먼저 짜면 프론트는 그 존재를 모른다.
> 명세가 바뀌면 이미 짠 코드를 버리게 된다. **노션 반영이 구현보다 먼저다.**

---

## 두 가지 흐름

### ① 새 API 설계 (레포 → 노션)

1. AI 와 함께 `.ai/api/{도메인}.md` 에 작성 — 상태 `📝 초안`
2. 팀 리뷰
3. **사람이 노션 API DB 에 반영**
4. 상태를 `✅ 확정` 으로 변경
5. 이제 AI 가 구현 가능

### ② 기존 명세 구현 (노션 → 레포)

1. 노션에서 해당 도메인 명세를 복사
2. `.ai/api/{도메인}.md` 로 저장, 상태 `✅ 확정`
3. 상단에 **노션 링크 + 복사 시점 날짜** 기록
4. AI 가 구현

> 확정 이후 명세가 바뀌면 **노션을 먼저 고치고** 레포 사본을 맞춘다. 반대 방향은 금지.

---

## 규칙

- 파일명은 `{도메인}.md` — 예: `auth.md`, `user.md`, `approval.md`
- **작업 중인 도메인만** 둔다. 전체를 복사하지 않는다.
  - 이전 모듈에서 노션과 1:1 미러한 명세가 2,025줄 / 72KB 까지 커져 "작업 전 반드시 읽어라" 규칙이 지켜질 수 없게 됐다.
- 사본과 노션이 다르고 상태가 `✅` 이상이면 → **노션이 맞다**
- API 를 건드린 PR 은 **"명세를 노션에 반영했다"** 체크 항목을 확인한다
