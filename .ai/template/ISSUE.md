# 🎫 Issue 작성 양식

> 🚫 **이슈 생성은 사용자가 직접 한다.** AI 는 `gh issue create` 등을 실행하지 않는다.
> 아래 양식대로 **제목 + 본문 텍스트만 제공**하면 사용자가 복사해서 직접 올린다.

> ⚠️ 팀 합의 전 초안. 확정되면 이 문구를 지운다.

---

## 제목

`[타입] 작업 내용` 형식.

| 타입 | 사용 시점 | 사용 템플릿 |
|------|----------|------------|
| `[Feat]` | 기능 구현·추가 | Feature |
| `[Fix]` | 오류·버그·예외 수정 | Bug |
| `[Task]` | 기능 외 작업 — 문서화·조사·설정·설계 | Task |
| `[Ref]` | 리팩토링·구조 개선 | Task |

---

## Feature 본문

````markdown
## 기능 설명

[무엇을 구현할지 간단히]

---

## 작업 범위

- `경로/패키지`: [작업 내용]
- `경로/패키지`: [작업 내용]

---

## 완료 조건

- [ ] 조건 1
- [ ] 조건 2

---

## 💬 공유 사항

[리뷰어 확인 사항 또는 공유 내용 — 없으면 "없음"]
````

---

## Bug 본문

````markdown
## 문제 지점

`경로/패키지`

---

## 버그 설명

[어떤 상황에서 어떤 문제가 발생하는지]

---

## 재현 방법

1. [단계 1]
2. [단계 2]

---

## 기대 동작

[정상이라면 어떻게 동작해야 하는지]

---

## 체크리스트

- [ ] 발생 위치를 작성했습니다.
- [ ] 재현 방법을 순서대로 작성했습니다.
- [ ] 다른 팀원 기능과 관련된 문제인지 확인했습니다.
````

---

## Task 본문

````markdown
## 담당자

- [이름]

---

## 배경 (Context)

[이 작업이 왜 필요한지, 어떤 배경에서 시작되었는지]

---

## 완료 조건

[완료되었다고 판단할 수 있는 구체적 조건]

---

## 액션 아이템

1. [작업 1]
2. [작업 2]
3. [작업 3]

---

## 기한

`YYYY.MM.DD (요일) HH:mm`

---

## 참고 자료

[관련 PR·이슈·문서 링크]
````

---

## 작성 규칙

- 작업 성격을 보고 타입 → 템플릿 순으로 판단한다.
- 리팩토링은 Task 템플릿을 쓰되 제목은 `[Ref]`.
- 확인 불가한 항목은 **"확인 필요"** 라고 적는다. 지어내지 않는다.
- GitHub 우측 필드(Assignees, Labels, Milestone, Projects)는 사용자가 직접 지정한다.
  추천값이 명확한 경우에만 응답 마지막에 짧게 제안한다.
- 민감 정보를 이슈 본문에 쓰지 않는다. ⚠️ **이 레포는 PUBLIC.**
