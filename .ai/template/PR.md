# 🔀 PR 작성 양식

> 🚫 **PR 생성은 사용자가 직접 한다.** AI 는 `gh pr create` 등을 실행하지 않는다.
> 아래 양식대로 **제목 + 본문 텍스트만 제공**하면 사용자가 복사해서 직접 올린다.

> ⚠️ 팀 합의 전 초안. 확정되면 이 문구를 지운다.

---

## 제목

`[타입] 작업 내용` 형식.

| 타입 | 사용 시점 |
|------|----------|
| `[Feat]` | 기능 구현·추가·생성 |
| `[Update]` | 기존 기능 수정·보완·변경 |
| `[Fix]` | 오류·버그·예외 수정 |
| `[Ref]` | 리팩토링·구조 개선 |
| `[Chore]` | 설정·빌드·문서·의존성 |

예: `[Feat] 이메일 인증 코드 발송 API 구현`

---

## 본문

````markdown
해당하는 항목에 체크해주세요.

- [x] ⭐ FEATURE
- [ ] 🌱 UPDATE
- [ ] 🐛 BUGFIX
- [ ] ♻️ REFACTOR
- [ ] 🔧 CHORE

---

## 📌 작업한 이슈
- Closes #N

---

## 🛠️ 작업 내용
- 변경 내용 1
- 변경 내용 2
- 변경 내용 3

---

## 📂 변경 범위
- `경로/패키지`: 변경 내용
- `경로/패키지`: 변경 내용

---

## 💬 리뷰어 확인 사항
- 확인이 필요한 부분 또는 공유 사항 (없으면 "없음")
````

---

## 작성 규칙

- 체크리스트는 제목의 타입과 **동일하게 1개만** 체크.
- 이슈 번호는 `Closes #N`. 다중 이슈는 `Closes #N + Closes #M`.
- 작업 내용은 실제 변경된 코드 기준 **2~4개 bullet**.
- 변경 범위는 실제 변경 파일을 보고 판단해서 작성.
- 확인 불가한 항목은 **"확인 필요"** 라고 적는다. 지어내지 않는다.
- 민감 정보(IP·키·비밀번호)를 PR 본문에 쓰지 않는다. ⚠️ **이 레포는 PUBLIC.**

## 작성 절차

1. `git status` / `git diff` 로 변경 파일 목록 + 내용 확인
2. 추가·수정된 클래스/설정 파일을 기준으로 bullet 작성
3. 경로별로 어떤 작업이 있었는지 정리
4. 제목 + 본문을 **텍스트로 제공** (실행하지 않음)
