## 0. 한 줄 정의

**발행은 홈택스에서 한다. 이 시스템은 발행된 계산서를 가져와 프로젝트에 붙여 보여준다.**

---

## 🚨 먼저 못 박을 것 — 이 도메인에 쓰기(발행)는 없다

| | 어디서 | 이 시스템 |
|---|--------|----------|
| **발행** | **홈택스** | ❌ 하지 않는다. 화면도 API 도 만들지 않는다 |
| **수집** | 재무 탭 P-42 | ✅ CSV 파싱 · 홈택스 API 조회 2경로 |
| **매칭** | 재무 탭 P-42 | ✅ 발주처 기준 후보 추천 → **사람이 확정** |
| **조회 · 연결** | 프로젝트 스텝 블록 (P-22A) | ✅ 프로젝트 쪽은 **읽기 전용.** 연결·해제는 재무 |

⛔ **어디에도 발행 버튼을 달지 마라.** 블록 타입 이름이 `TAX_INVOICE_VIEW`(조회)인 것과 같은 이유다.
발행을 시스템 밖에 두면 [`PERMISSION.md`](../../global/PERMISSION.md) §5 *"프로젝트 쪽은 전원 읽기 전용"* 이 자동으로 지켜진다.

> ⚠️ **입금(`PAY-V1`)과 대칭이 아니다.** 입금은 이 시스템이 **확정 주체**지만,
> 계산서는 **홈택스가 원본**이고 여기는 사본이다. 그래서 수정·삭제 요구사항이 거의 없다.

## 1. 범위

### 1-1. 만든다

| 영역 | 화면 | 내용 |
|------|------|------|
| 수집 | P-42 | CSV 파싱 업로드 · 홈택스 API 조회 · 출처 기록 · 중복 차단 |
| 프로젝트 매칭 | P-42 | 발주처 기준 후보 추천 · 사람 확정 · 매칭 해제 |
| 목록 · 조회 | P-42 | 기간 · 프로젝트 · 매칭 여부 필터 |
| 블록 연결 | P-22A | 조회 블록 생성 · 재무가 연결/해제 · 읽기 전용 표시 · **삭제 잠금** |

### 1-2. 안 한다 (명시)

| 항목 | 왜 |
|------|-----|
| **발행 · 수정 · 취소** | **홈택스에서 한다.** 여기서 고치면 원본과 어긋난다 |
| **직접 등록 (손입력)** | 원본이 홈택스에 있으니 **항상 가져올 수 있다.** 손입력을 열면 원본 없는 계산서가 생긴다.<br/>⚠️ 입금(`PAY-001`)에는 직접 등록이 있다 — 은행 자료 없이도 재무가 아는 경우가 있어서다. **계산서엔 그 경우가 없다** |
| **매입 계산서** | 우리가 **받은** 계산서는 이 도메인 밖이다 → `INV-09` |
| **역발행 · 수정세금계산서 구조화** | 홈택스에서 처리된 결과가 수집으로 들어온다. 상태머신을 만들지 않는다 |
| **발행 상태 관리** | 조회 목적뿐이다. 행이 있으면 발행된 것이다 |
| **입금 매칭** | [`PAY-V1.md`](PAY-V1.md) 소관 (같은 담당, 다른 문서). **계산서와 입금은 별개 사건이다** |
| **청구서 작성·결재** | 프로젝트 쪽 파일 블록 + 결재 블록 소관 |
| **실적 등재 (P-43)** | `performance` 테이블 없음 ([`HANDOFF.md`](../HANDOFF.md) T2) |

## 2. 요구사항

### 2-A. 수집 (`TAX`) — P-42

| ID | 대분류 | 중분류 | 소분류 | 요구사항 | 수용 기준 |
|----|--------|--------|--------|---------|----------|
| **TAX-001** | 세금계산서 | CSV 수집 | 파일 업로드 | 재무 담당자는 홈택스에서 내려받은 CSV 를 올려 계산서를 일괄 등록한다 | `page_code='FINANCE'` + `EDITOR` 가 아니면 **403**. 파싱된 행 수만큼 `tax_invoice` 생성 |
| **TAX-002** | 세금계산서 | CSV 수집 | 컬럼 매핑 | 사용자는 CSV 의 어느 열이 발행일 · 공급가액 · 세액 · 합계 · 공급받는자인지 지정한다 | 매핑 없이 업로드하면 **400** |
| **TAX-002B** | 세금계산서 | CSV 수집 | **매출분만** | **우리가 발행한 것(매출)만** 수집한다. 받은 것(매입)은 수집하지 않는다 | 공급자가 우리 사업자번호가 아닌 행은 건너뛴다. 건너뛴 수가 표시된다. **안 막으면 우리가 받은 계산서가 프로젝트에 붙는다** |
| **TAX-003** | 세금계산서 | CSV 수집 | 부분 실패 안내 | 파싱 실패 행이 있어도 나머지는 저장된다 | `성공 N건 / 실패 M건` 과 실패 행 번호·사유가 반환된다. 전체 롤백하지 않는다 |
| **TAX-004** | 세금계산서 | API 수집 | 홈택스 조회 | 시스템은 홈택스 API 로 발행 내역을 가져와 등록한다 | 수집된 행이 CSV 경로와 **같은 `tax_invoice` 구조**로 저장된다 |
| **TAX-005** | 세금계산서 | API 수집 | 실패 격리 | 연동이 실패해도 CSV 경로는 살아 있다 | API 오류가 화면을 막지 않는다. 실패 사실이 로그에 남는다 |
| **TAX-006** | 세금계산서 | 수집 공통 | 중복 차단 | 같은 계산서를 두 번 수집하지 않는다 | 승인번호가 같은 행은 **건너뛴다**(에러 아님). 건너뛴 수가 표시된다 |
| **TAX-006B** | 세금계산서 | 수집 공통 | 승인번호 필수 | 승인번호가 없는 행은 수집하지 않는다 | 해당 행은 실패로 집계된다. **키 없이 넣으면 중복을 영영 못 막는다** |
| **TAX-007** | 세금계산서 | 수집 공통 | 출처 기록 | 각 계산서는 **어떻게 들어왔는지**를 기록한다 | CSV · 홈택스 API 를 구분해 저장·표시한다 |
| **TAX-007B** | 세금계산서 | 수집 취소 | 잘못 수집분 제거 | 재무는 잘못 수집된 계산서를 지울 수 있다 | soft delete. **블록에 연결돼 있으면 409** — 먼저 `TXL-007` 로 해제해야 한다 |
| **TAX-008** | 세금계산서 | 수집 공통 | 미매칭 저장 | 수집된 계산서는 **미매칭 상태로** 들어온다 | `project_id` 가 `NULL` 이다. 수집이 매칭을 겸하지 않는다 |
| **TAX-009** | 세금계산서 | 목록 | 조회 · 필터 | 사용자는 기간 · 프로젝트 · 매칭 여부로 목록을 좁힐 수 있다 | 각 조건이 단독·조합으로 동작한다. 미매칭 건이 상단에 온다 |
| **TAX-010** | 세금계산서 | 권한 | 조회 주체 | 프로젝트 참여자(실무자)는 재무 탭 목록에 들어갈 수 없다 | `page_code='FINANCE'` 행이 없으면 **403**. 실무자는 블록으로만 본다 |

### 2-B. 프로젝트 매칭 (`TXM`) — P-42

| ID | 대분류 | 중분류 | 소분류 | 요구사항 | 수용 기준 |
|----|--------|--------|--------|---------|----------|
| **TXM-001** | 세금계산서 | 매칭 | 프로젝트 지정 | 재무는 계산서를 프로젝트에 매칭한다 | `tax_invoice.project_id` 가 채워진다. `FINANCE`+`EDITOR` 아니면 **403** |
| **TXM-002** | 세금계산서 | 매칭 | 발주처 후보 추천 | 시스템은 계산서의 **공급받는자**와 프로젝트 **발주처**가 같은 프로젝트를 후보로 올린다 | 발주처 일치 → 발행일 근접 → 금액 순으로 정렬된다 |
| **TXM-003** | 세금계산서 | 매칭 | 사람이 확정 | **확정 버튼은 사람이 누른다** | 자동 확정 경로가 코드에 존재하지 않는다. **한 발주처에 프로젝트가 여러 개일 수 있다** |
| **TXM-004** | 세금계산서 | 매칭 | 후보 없음 허용 | 발주처가 안 맞아도 재무가 직접 프로젝트를 고를 수 있다 | 후보 목록 밖의 프로젝트를 검색해 지정할 수 있다 |
| **TXM-005** | 세금계산서 | 매칭 해제 | 해제 주체 | **재무만** 매칭을 해제할 수 있다 | `FINANCE`+`EDITOR` 아니면 **403** |
| **TXM-006** | 세금계산서 | 매칭 해제 | 블록 연결 시 차단 | 블록에 연결된 계산서는 매칭을 해제할 수 없다 | **409.** 먼저 `TXL-007` 로 블록 연결을 해제해야 한다 |

### 2-C. 블록 연결 (`TXL`) — P-22A

| ID | 대분류 | 중분류 | 소분류 | 요구사항 | 수용 기준 |
|----|--------|--------|--------|---------|----------|
| **TXL-001** | 세금계산서 | 블록 생성 | 조회 블록 생성 | 실무자는 정산 스텝에 세금계산서 조회 블록을 만들 수 있다 | `block.type='TAX_INVOICE_VIEW'` 로 생성된다. `tax_invoice_confirm` 상세는 **연결 시점에** 생긴다 |
| **TXL-001B** | 세금계산서 | 블록 생성 | **스텝당 1개** | 한 스텝에는 세금계산서 조회 블록을 **하나만** 만들 수 있다 | 두 번째 생성은 **409.** 회차(=스텝) 하나에 계산서가 여러 장이면 정산현황의 `계산서` 열이 어느 것인지 알 수 없다 → INV-08 · [`PAY-V1.md`](PAY-V1.md) INV-07C 와 짝이다 |
| **TXL-002** | 세금계산서 | 블록 연결 | 연결 주체 | **재무만** 블록에 계산서를 연결할 수 있다 | `FINANCE`+`EDITOR` 아니면 **403**. `linked_by` 에 `employee_id` 기록 |
| **TXL-003** | 세금계산서 | 블록 연결 | 선후 관계 | 블록 연결 전에 **프로젝트 매칭이 먼저** 되어 있어야 한다 | `project_id` 가 `NULL` 인 계산서를 블록에 연결하면 **400** |
| **TXL-004** | 세금계산서 | 블록 연결 | 프로젝트 일치 | 연결하려는 블록은 **매칭된 그 프로젝트**에 속해야 한다 | `block.project_id ≠ tax_invoice.project_id` 면 **400** |
| **TXL-005** | 세금계산서 | 블록 연결 | 1블록 1계산서 | 블록 하나에 계산서 하나만 붙는다 | `tax_invoice_confirm` 에 **`UNIQUE(block_id)`** (1:1). 두 번째 연결은 **409** → [`ERD.md`](ERD.md) §4-2 |
| **TXL-005B** | 세금계산서 | 블록 연결 | 1계산서 1블록 | 계산서 하나는 블록 **한 곳에만** 붙는다 | `tax_invoice_confirm` 에 **`UNIQUE(tax_invoice_id)`**. 이미 연결된 계산서를 다른 블록에 연결하면 **409.** 같은 계산서가 두 회차에 잡히면 안 된다 |
| **TXL-006** | 세금계산서 | 블록 표시 | 읽기 전용 | 프로젝트 참여자는 계산서 정보를 **읽기만** 한다 | **블록에 발행·수정 버튼이 없다.** 스텝 `EDITOR` 여도 쓰기 요청은 403 |
| **TXL-007** | 세금계산서 | 연결 해제 | 해제 주체 | **재무만** 연결을 해제할 수 있다 | `FINANCE`+`EDITOR` 아니면 **403** |
| **TXL-008** | 세금계산서 | 블록 표시 | 표시 항목 | 사용자는 블록에서 발행일 · 공급가액 · 세액 · 합계를 본다 | 미연결이면 `대기` 로 표시된다. 빈 화면이 아니다 |
| **TXL-009** | 세금계산서 | 블록 삭제 | 블록 잠금 | 계산서가 연결된 블록은 삭제할 수 없다 | **409** + "재무가 연결을 해제해야 합니다" 안내 |
| **TXL-010** | 세금계산서 | 블록 삭제 | 스텝까지 잠금 | 그 블록이 들어 있는 **스텝도** 삭제할 수 없다 | **409.** 블록만 막고 스텝을 열어두면 우회로가 생긴다 |
| **TXL-011** | 세금계산서 | 템플릿 | 담기는 범위 | 템플릿에는 블록 껍데기만 담긴다 | 연결된 계산서는 복사되지 않는다. 적용된 블록은 미연결 상태로 생성된다 |

## 3. 불변식 — 절대 깨지면 안 되는 것

| ID | 규칙 | 왜 |
|----|------|-----|
| **INV-01** | **이 시스템은 세금계산서를 발행하지 않는다** | 원본은 홈택스다. 여기서 만들거나 고치면 **두 곳의 숫자가 갈라지고 어느 쪽이 맞는지 아무도 모른다** |
| **INV-02** | **수집은 자동, 매칭은 사람** | 발주처가 같아도 프로젝트는 여러 개일 수 있다. 자동 확정하면 남의 프로젝트에 계산서가 붙는다 |
| **INV-03** | **수집 API 가 죽어도 CSV 경로는 산다** | 홈택스 연동 장애로 재무 업무가 멈추면 안 된다 |
| **INV-04** | **같은 계산서를 두 번 수집하지 않는다** | 중복 행이 들어오면 정산 화면의 계산서 금액이 조용히 두 배가 된다 |
| **INV-05** | **수집 직후 `tax_invoice.project_id` 는 `NULL` 이다** | 홈택스는 프로젝트를 모른다. **미매칭 상태가 정상이다** ([`PAY-V1.md`](PAY-V1.md) INV-03 과 같은 구조) |
| **INV-06** | **연결·해제는 재무만** | 실무자가 풀 수 있으면 TXL-009 잠금이 무의미하다 |
| **INV-07** | **연결되면 블록과 스텝 둘 다 삭제 잠금** | 블록만 막고 스텝을 열어두면 스텝을 지워 블록을 없애는 우회로가 생긴다 ([`PAY-V1.md`](PAY-V1.md) INV-05 와 동일) |
| **INV-08** | **계산서와 입금을 직접 연결하지 않는다** | 회차(=정산 스텝)가 둘을 묶는다. 직접 FK 를 걸면 분할입금·분할발행에서 즉시 깨진다.<br/>⚠️ 이게 성립하려면 **스텝 하나에 회차 하나 · 계산서 블록 하나**여야 한다 → [`PAY-V1.md`](PAY-V1.md) `INV-07C`·`PCB-001B` · 이 문서 `TXL-001B` |
| **INV-09** | **매입 계산서를 들이지 않는다** | 홈택스 내역에는 **우리가 받은 계산서도 섞여 있다.** 안 거르면 매입분이 프로젝트 수금액으로 잡혀 매출이 부풀려진다 |
| **INV-10** | **이 시스템은 계산서를 발행하지 않으므로 수정도 없다** | 고칠 일이 생기면 홈택스에서 고치고 **다시 수집한다.** 사본을 손으로 맞추기 시작하면 원본과 갈라진다 |
| **INV-11** | **회차 번호는 `block_payment_confirm` 한 곳에만 산다** | 계산서 쪽에 `round_no` 사본을 두면 실무자가 회차를 고칠 때 두 값이 갈라지고, **어느 쪽이 맞는지 아무도 모른다** ([`PAY-V1.md`](PAY-V1.md) INV-07 과 같은 이유) → [`ERD.md`](ERD.md) §0 결정 5 |
